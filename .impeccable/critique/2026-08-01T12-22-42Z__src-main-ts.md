## Overall Impression

這是一個有清楚領域模型與交付終點的工具型 PWA，但目前把太多資料模型與管理能力同時呈現在現場工作流中。最大的機會不是單純換色或加裝飾，而是把「今日要完成什麼、資料是否已保存、下一步要做什麼」變成第一層介面。

## What's Working

1. 固定預覽與「複製完整日報」提供清楚的交付終點（`src/main.ts:92`）。
2. 工種、廠商、工項、獨立進料與連接關係反映真實施工資料組織（`src/main.ts:72-74`）。
3. 按鈕普遍具備約 44px 觸控高度，且處理了 safe-area 與固定操作位置（`src/styles.css:1`、`src/daily/daily.css:1`）。

## Cognitive Load

Intrinsic load 偏高且合理：施工、進料、聯絡、特殊事項與水位本身就有領域複雜度。Extraneous load 中高，主要來自主頁模組 tab + 日報四個 tab + 固定預覽 + 浮動新增、設定頁 8 個管理區塊、工種卡片內同時放排序／展開／工項／連接／完成／刪除，以及材料的普通／獨立／連接／轉換狀態。高風險決策包括完成工種、連接獨立進料、刪除材料類型、覆蓋重複水位與放棄未保存修改。

## Emotional Journey

- 開始：LOCAL ONLY 帶來部分安心。
- 輸入中：多層分類與展開卡片讓使用者持續確認目前層級。
- 高風險操作：沒有明確保存與備份狀態，刪除／覆蓋使用原生對話框，信任感下降。
- 完成：預覽與複製提供終點，但草稿存在時 disabled 的複製按鈕未直接告訴使用者下一步。
- 結尾：複製後缺少「已複製、包含幾個工種、資料已保存」的成果回饋。

## Priority Issues

### [P0] 離線資料信任沒有落地

**Why it matters：**產品承諾是 IndexedDB、本機保存與歷史不遺失，但備份頁目前只是未來功能說明，沒有匯出、還原、備份狀態或版本資訊（`src/main.ts:98`、`README.md:24-26`）。

**Fix：**Header 顯示離線／已保存／最後保存時間；提供完整備份匯出、檔案還原、還原前預覽；破壞性操作提供 undo 或可恢復封存；複製後顯示輸出範圍與保存狀態。

**Suggested command：**`$impeccable harden`

### [P1] 固定預覽與浮動新增搶佔手機工作區

**Why it matters：**`bottom-preview` 與 `floating-add-trade` 同時固定，預覽內容可變長，可能遮住表單與操作；目前以 `padding-bottom:18rem` 等估算補位（`src/daily/debug-layout.css:1`）。

**Fix：**預覽改為可收合 bottom sheet，預設只保留摘要與狀態；新增工種移到工程列表標題旁；以實際 safe-area／可視高度處理內容，不依賴固定估算；日報與水位採同一預覽模式。

**Suggested command：**`$impeccable adapt`

### [P1] 今日工作與資料管理混在同一資訊架構

**Why it matters：**現場人員完成單一日報，卻要同時理解日報／水位、四個日報 tab、設定八個區塊與水位三個 subtabs，增加不必要的決策成本。

**Fix：**主流程聚焦今日紀錄與輸出；設定改為次級入口，分成基本資料、施工資料、進料資料、系統資料；首次操作只要求日期／工地／工種，材料連接與模板採 progressive disclosure。

**Suggested command：**`$impeccable distill` 或 `$impeccable shape`

### [P1] 破壞性與特殊操作不可發現、不可替代

**Why it matters：**拖曳排序只有 `⠿`，沒有鍵盤或按鈕替代；刪除、解除連接、類型轉換埋在卡片內；材料摘要是可點擊 `<header>` 而非原生 button，鍵盤與語意風險高（`src/main.ts:63`、`src/main.ts:69`、`src/main.ts:72`）。

**Fix：**提供上移／下移／最前／最後；刪除顯示影響範圍；以明確狀態區塊取代空白 `visibility:hidden` chip；摘要改用 button／details 或完整 keyboard interaction。

**Suggested command：**`$impeccable audit`

### [P2] alert／confirm／prompt 過度主導回饋

**Why it matters：**水位改名、刪除、重複匯入與日報多個危險操作使用原生對話框，中斷手機上下文，也無法提供頁內可追蹤結果（`src/water-level/controller.js:17-20`）。

**Fix：**改為 inline editor、dialog 或 bottom sheet；保存後顯示非阻塞 toast；匯入顯示成功／略過／失敗筆數與逐筆結果；將未完成工種直接列為可點擊下一步。

**Suggested command：**`$impeccable clarify` + `$impeccable harden`

## Persona Red Flags

### 現場快速填報員

- 需要理解四個 tab、卡片展開、工種完成與固定預覽。
- 浮動「＋ 工種」不在工程列表語意區附近，容易誤觸。
- 固定預覽佔用長表單的手機可視高度。
- 沒有明確已保存狀態，離線時不敢離開頁面。

### 現場主管／複核者

- 草稿／完成狀態只在卡片右側，缺少待處理清單。
- 複製 disabled 時沒有直接列出未完成項目與跳轉。
- 預覽固定在底部，不利於比較單一工種與完整輸出。

### 第一次使用的替代人員

- 必須先理解工種與工項管理、材料類型、獨立進料等術語。
- README 暗示可備份，但介面沒有真正的匯出／還原。
- 水位匯入需要特定文字格式，沒有範例插入與解析前預覽。

## Minor Observations

- CSS token 分散於 `styles.css`、`daily.css`、`material.css`、`water.css`，且 page gap 等變數重複定義。
- 繁中產品使用 `FIELD NOTEBOOK`、`DAILY OUTPUT` 等英文 eyebrow，對現場使用者價值有限。
- `README.md` 描述 `src/main.js`、`src/core`、`src/modules`，但目前入口與架構已是 TypeScript／其他目錄。
- debug 畫面 `databaseVersion` 顯示 4，但實際資料庫定義為 6（`src/main.ts:99`、`src/db/database.ts:5`）。
- 水位最近三天保留政策應在介面明確說明。
- 缺少明確 focus style；水位 tab 缺少 `role="tablist"`、`aria-selected`，頂部導航缺少 `aria-current`。
- 設定互動會整體 render，focus preservation 不一致；工項位置的 inline `1fr 1fr 2fr` 在窄螢幕可能過窄（`src/main.ts:52`）。

## Questions to Consider

1. 如果現場人員只剩 30 秒，第一個畫面是否真的只留下今天要填的資料？
2. 為什麼日報輸出預覽在輸入過程中需要持續佔據手機底部？
3. 普通／獨立進料／連接是使用者真正需要理解的概念，還是應由 UI 自動推導？
4. 「離線、資料只在本機」目前是安心訊息，還是因為沒有保存與備份狀態而變成新的焦慮來源？
