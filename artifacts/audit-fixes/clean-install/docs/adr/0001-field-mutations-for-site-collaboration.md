# ADR 0001：共編以欄位修改寫入，快照作為讀取模型

## 決策

施工日報與水位共編的寫入協定採用帶唯一操作 ID 的欄位修改；伺服器在單一交易中驗證工地編輯權限、去重、依穩定 ID 合併並遞增文件版本。既有快照 RPC 繼續作為舊版佇列的相容路徑，並保有其版本檢查。

## 背景與取捨

整份快照加單一 revision 能偵測衝突，卻會把不同欄位的正常同時編輯變成衝突。欄位修改增加了 mutation 格式與伺服器合併邏輯，但讓不相干修改共存；同一欄位則以最後成功寫入的交易為準。已刪除識別由伺服器保存，避免離線舊操作復活資料。

## 後果

客戶端必須保存可升級的 outbox 協定版本並只提交變更欄位；訂閱只作通知，收到後仍以權限受控的增量拉取取得資料。UI 本機暫態（焦點、游標、展開狀態與未提交輸入）不進入 mutation 或遠端快照。
