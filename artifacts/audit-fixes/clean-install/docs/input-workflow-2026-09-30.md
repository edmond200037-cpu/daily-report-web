# 日報輸入流程修訂

## 操作流程

手機手勢補充：工項左側握把長按排序、左滑放開刪除，刪除後可復原；已移除更多選單與排序、刪除按鈕。新增下一筆開啟空白工程並聚焦工種，工種欄維持該工地記憶的原生搜尋建議。定稿先保存本機快照並複製，後續記憶更新與草稿同步不阻塞複製；剪貼簿拒絕時保留定稿並提示重按複製。此輪 172 個測試與正式建置通過，尚未量測手機實際延遲或驗證觸控手勢。

手機版後續修訂：搜尋／加入列固定在清單上方，仍可用「、」一次加入多項；項目逐行向下排列。工地與日期同排，工種／廠商／人數同排。點選工項可直接改字，位置與備註在該項內展開；同名工項即時提醒，不同位置仍可保留。此輪 170 個測試與 production build 通過；尚未執行實際手機瀏覽器驗證，也未發布到 GitHub Pages。

1. 選擇有權限的工地，載入該工地日報草稿與記憶。日報與水位各自保留日期與歷史。
2. 同列輸入工種、廠商、人數；工項搜尋支援已確認與待審核資料。
3. 使用「、」、Enter 或「加入」連續新增工項。中文組字完成前不切分。
4. 點選工項直接改文字，上方可開啟位置／樓層、備註及排序／刪除。每項保留穩定 ID。
5. 缺漏自動顯示；「收合」保存目前資料，「儲存並新增下一筆」延用工種。預覽會保存尚未送出的尾端文字。

## 記憶規則

- 沿用既有記憶資料與審核頁。待審核項目同樣上傳後端，供同工地成員搜尋與計數。
- 工項加入／套用、施工列收合或新增下一筆、進料與聯絡事項保存，以及切換工地／日期時記錄有效套用。
- 有效套用由日期、來源紀錄 ID、欄位種類與正規化文字識別。同一紀錄重試、往返修改後改回原值不重複計數；另一筆紀錄或另一日期算新套用。
- 前端記錄離線事件；後端 `apply_memory_application` 去重後累加，超過三次即第 4 次自動確認。人工確認仍可使用。
- 工種、廠商按施工列計數；工項按工項紀錄計數。單純預覽、自動保存、同步重試不增加次數。
- 本機離線次數是暫存值，連線後以後端總數為準。

## 模組邊界

| 模組 | 責任 |
| --- | --- |
| `src/daily/work-input.ts` | 工項互動、搜尋、組字、位置／備註面板 |
| `src/daily/input-workflow.ts` | 頓號解析、完整性、編輯意圖合併 |
| `src/settings/memory-applications.ts` | 套用事件、去重、本機暫存計數與 outbox |
| `src/sync/workspace-lock.ts` | 工地切換與同步共用互斥鎖 |
| `src/sync/engine.ts` | RPC 路由、佇列重試、遠端合併 |

保存以編輯基準計算欄位差異，避免舊畫面蓋掉其他人的不同欄位修改；工地切換前保存舊工地，完成後才載入新分區。水位拉取後重套所有尚未同步的修改。

先部署 SQL，再發布前端。新前端使用獨立的 `apply_memory_application` RPC，舊後端缺少此函式時保留失敗佇列，不假裝已成功計數。部署前先於測試環境備份及確認 migration 清單；可使用 Supabase CLI 的 `db push --dry-run` 檢查待套用檔案。

## 驗證範圍

本機結果：167 個測試通過；TypeScript 與 Vite production build（含 Service Worker）通過；`git diff --check` 通過。

- 單元與 IndexedDB 整合測試涵蓋頓號切分、自動完整性、跨工地隔離、歷史篩選、遠端欄位保留、重送去重及第 4 次自動確認。
- TypeScript 與 production build 為本機驗證；不代表實際瀏覽器或雲端成功。
- 瀏覽器工具權限遭拒，本次未完成手機版視覺、中文 IME 真實輸入及雙視窗操作驗證。
- SQL 執行工具要求核准，但目前核准政策為 never；本次未部署 migration，也未驗證線上多人共同計數。
- 部署後需以兩位可編輯成員各新增兩筆相同工項驗證累積 4 次、重送不增加、待審核可互搜、檢視者不能寫入，並測試離線後切換工地重連。
- 定稿快照目前仍為本機資料；介面明確區分「草稿雲端同步」與「本機定稿」。
