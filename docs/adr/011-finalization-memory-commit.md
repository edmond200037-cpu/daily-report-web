# ADR-011：定稿作為記憶提交點並保留草稿

## 決策

「定稿且複製」是整份日報將可重用內容提交至記憶模組的唯一自動學習時點。成功定稿後保留 `live_report_draft` 的完整內容、條目識別與完成狀態，不再建立空白當日草稿。

定稿仍建立不可回寫的 `daily_reports` 快照。系統以實際輸出文字的內容指紋判斷是否發生會影響輸出的修改：

- 指紋與最近一次成功定稿相同時，只再次複製既有 `outputText`，不得新增快照或重複累加記憶使用次數。
- 指紋不同時，才建立新的不可變快照，並在同一次提交中累加該版內容的記憶使用次數。
- 快照或記憶提交任一失敗時，整次定稿失敗；原草稿與既有記憶不得只完成一半。

聯絡事項選定工種後，只自動填入該工種的一個既有正式廠商，並從該工種共用的 `trade_tasks` 正式記憶提供施工項目建議。聯絡事項的普通儲存只保存草稿，不在此時建立候選或累加使用次數。

工程條目與聯絡事項使用相同的廠商自動套用規則：只考慮所選工種下的正式廠商，先依 `lastUsedAt` 由新到舊排序；時間相同時再依 `usageCount` 由多到少排序；仍相同時以標準化名稱排序，確保結果穩定。

成功定稿只提交以下可重用欄位：

- 工地、工種、廠商。
- 工程工項、聯絡施工項目、位置。
- 材料類型、品名、規格、單位、供應商。

施工人數、進料數量、樓層、日期、備註與特殊事項屬於單日事實，不得自動寫入記憶模組。

新記憶先以候選狀態保存，不得立即用於自動填入或一般建議。候選符合以下條件時自動轉為正式主檔：

- 同一標準化候選出現在三次 `outputText` 指紋不同的成功定稿中。
- 同一份定稿內即使出現多次，同一候選最多只累加一次定稿使用次數。
- 指紋未變的「再次複製」不得累加定稿使用次數。
- 第三次成功提交與候選轉正式必須屬於同一原子交易；交易失敗時兩者都不得生效。
- 記憶審核可在門檻前人工確認；人工駁回或刪除後，後續重新出現的內容依既有候選建立規則處理。

## 後果

- 工程條目與聯絡事項的施工項目共用同一個 `trade_tasks` 記憶集合；介面名稱不同，不建立第二套聯絡事項工項記憶。
- 白名單內的可重用內容統一由成功定稿交易提交為候選或累加既有記憶；未列入白名單的欄位不得以推測方式加入。
- 候選以「不同定稿的出現次數」判斷三次自動確認，不得直接拿同一份日報中的重複欄位數量或再次複製次數充當門檻。
- 保留草稿後，使用者可直接再次複製，或修改會影響輸出的內容後建立下一份定稿快照。
- UI 展開／收合、目前頁籤與其他不影響輸出的暫時狀態，不得使內容指紋失效或建立新快照。
