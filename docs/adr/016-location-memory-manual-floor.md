# ADR-016：位置記憶手動樓層

## 背景

位置記憶（`location_memories`）原本只存位置文字。現場常以「東側｜3F～5F」成對使用，使用者要求位置記憶可附帶起訖樓層，並在日報選定位置時帶入。CLAUDE.md §4-8 規定樓層是單日事實，不得自動寫入記憶。

## 決策

- `NamedMemory` 新增選填 `startFloorRaw`、`endFloorRaw`，只用於位置；存 `normalizeFloor` 的正規化字串，空字串或缺省代表未設定。不改 `DB_VERSION`、不加 store。
- 樓層**只能在設定的位置頁手動填寫**（`saveLocationMemory`）。格式錯誤拒絕存檔；起訖顛倒時自動交換，不詢問。
- 自動學習（定稿記憶提交、有效套用累計）只處理位置文字，**不讀寫、不覆蓋**既有樓層；整列更新沿用 `...current` 展開而保留樓層。這不違反 §4-8：樓層是使用者明確手動維護的主檔屬性，不是單日事實被自動記憶。
- 日報位置欄提供 `datalist` 建議（只含正式位置，候選不出現）。位置欄 `change`（非 `input`，避免 IME 問題）時：符合記憶則連結 `locationId` 與名稱；**僅當該工項起始與結束樓層皆空白**才帶入記憶樓層；已有任一樓層不覆蓋。不符合任何記憶則解除 `locationId`、保留輸入。唯讀工地不寫入。
- 位置記憶的樓層變更不回寫草稿或定稿；改名沿用既有 `syncRename` 只同步名稱快照。
- 備份格式不變：匯出原樣輸出、匯入 `copyNamedMemory` 以展開保留額外欄位；既有同名位置於合併時略過，不更新樓層。同步以整列為 payload，新欄位自然同步。

## 後果

- 日報輸出文字與 formatter 不變；帶入的樓層與手填樓層在草稿中無差別。
- 舊資料無樓層欄位，行為與先前相同。
