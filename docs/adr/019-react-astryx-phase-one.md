# ADR-019：React 與 Astryx 的第一階段介面遷移

日期：2026-11-24。使用者明確授權更換日報版面與全站導覽外殼；本決策不擴大資料、同步、定稿或水位的修改範圍。

## 邊界與組成

- React 19 的 `AppShell`、`Theme` 與主要導覽由 `src/app/react/` 負責。
- `LegacyRoute` 移動原本的 `app` 容器，保留其事件、帳號非同步載入與水位控制器；共用外殼供應主要頁籤，舊頁內重複頁籤移除。
- 只有 `#daily` 使用 `src/daily/react/`；歷史、設定、帳號及水位保留既有渲染器。
- 舊 CSS 在建置時限定於 `.legacy-route`，避免舊的原生 `button/input` 選擇器覆蓋 Astryx。
- `site-paper` 由 Astryx theme editor 建立；設定和產生模組保留於專案，PNG/HTML 預覽不提交。
- Astryx Core、CLI 與 Neutral 主題固定為 0.7.17；保留原 injectManifest 與兩種 BASE_PATH。

## 手機工作流

1. 點確認過的工種晶片，沿用 `memoryOrder` 與 `recentTradeVendor` 帶入。
2. 使用人數加減或數字欄位；工項建議與頓號拆分沿用既有純函式。
3. 常用進料依材料類型的正式記憶帶入品名、規格、單位與供應商，數量保持空白；資料不齊時可展開編輯。
4. 位置、樓層、備註、聯絡與特殊事項沿用原本資料模型及控制器／repository。
5. BottomSheet 提供工種選擇、預覽與原本的定稿複製；不建立新的輸出或記憶提交規則。

## 寫入與暫態

`dailyUi` 只通知 React 重畫。工項尚未加入的文字保存在記憶體 Map，以工作區與工種識別區隔；展開、收合、預覽與焦點不呼叫控制器 `update/flush`。欄位修改及確認加入走既有控制器，進料與聯絡儲存及定稿走既有 action dispatcher。

聯絡暫存與舊版未提交工項也僅在本次工作階段保存於記憶體。舊版 localStorage 暫存仍可讀取，但未提交工項只回到輸入器，不進入舊版自動提交佇列；必須明確按加入才建立工項。取消、重開面板和輸入搜尋不另建儲存路徑。

日期切換共用 `switchDailyDate`，保留 `dateSwitching`、`app.inert`、`activeSyncEpoch` 與舊結果作廢規則；共用工地切換仍使用原帳號控制器。唯讀判斷仍以 `isReadOnlySite` 為準。

工項握把與整列排序沿用既有意圖、預覽、插槽、自動捲動及失敗回復。左滑採共用 `swipeDeletes` 的 72px／水平方向門檻；六秒復原只保留於 UI 記憶體。

## 測試與輸出基準

新版契約改以 React 實際輸出的 HTML、既有純邏輯與瀏覽器操作確認。原本人工答案與未修改的 HEAD formatter 已有全形日期括號、分隔線長度／空行等差異；原答案保留於 `tests/e2e/fixtures/expected/`。

本次另外以 `098d9efe3e98dcfb5b833f190e8d52f4f36ed4cd` 的未修改 formatter 捕捉十份 `current-output` 快照；`baseline.json` 記錄來源 commit 與 SHA-256。E2E 以這些固定文字逐字比較真正剪貼簿，並另存與原人工答案的差異。此基準是遷移前現行行為，並非宣告人工答案的格式需求已完成。

### 取消或替換的舊版面斷言

- 固定 60px／74px 摘要列、四欄 CSS 格線及指定字重／色碼選擇器：改為 Astryx List／主題的契約，保留資料欄位、狀態與長文字不溢出的驗證。
- 黏頂四顆新增按鈕、舊捲動標亮與日期第二列的 CSS 排法：使用者改為底部五項操作與新頁首，保留路由、工地及日期切換行為。
- 「不得顯示標題、說明或任何空狀態」：使用者核定常用工種、進料等具名區段，保留四區段順序及草稿內容。
- 「施工沒有取消新增」：使用者要求新版保留取消功能，改驗證穩定 ID、只對目前新增條目顯示、唯讀禁止與六秒復原。
- 「建議包含候選記憶」：依本次硬限制，改為只呈現正式記憶；明確搜尋仍可建立新文字。
- 舊 datalist／操作選單 DOM、工項上下移按鈕及固定 450px 空白卡高度：改為元件欄位、位置／備註入口及握把；保留樓層正規化、返回焦點、排序回復及刪除復原。ADR-007 已接受不提供工項排序替代按鈕。
- 新增項目後自動聚焦文字欄位、舊頁首固定標題 DOM：改為只捲動至新增內容，文字欄位由使用者點擊才喚出鍵盤；頁首以主要導覽與日期／工地控制呈現。原本資料及新增動作仍保留。
- 人工答案逐字斷言：保留原答案與差異報告，遷移驗收改比對上述未修改 HEAD 的固定輸出；不改 formatter 來迎合過期答案。

正式 OAuth、Realtime、實機 IME／手勢與部署快取仍須另行驗收。
